# Distributed RepoJudgeBench on AWS (Terraform)

One master and five workers in a private VPC run the whole experiment: benchmark
construction in Docker, judging with llama.cpp, analysis and the paper.
AWS account: `602170263568` (Terraform refuses to run against any other account).

## Architecture

| Component | Where | What runs there |
|---|---|---|
| VPC `10.42.0.0/16` | one availability zone | public subnet `10.42.1.0/24` (master, NAT gateway), private subnet `10.42.2.0/24` (workers) |
| Master (`m7i.xlarge`, 100 GB) | public subnet | orchestrator (`scripts/orchestrate.sh`), item builder, static baseline, analysis, LaTeX |
| 5 workers (`c7i.4xlarge`, 250 GB) | private subnet, no public IPs | Docker (task images), benchmark build shard, llama.cpp judges |
| NAT gateway | public subnet | outbound internet for the workers (Hugging Face, Docker mirror, PyPI, GitHub) |

Communication: the operator reaches only the master over SSH; the security group admits only
the operator's current public IP, detected by `run_experiment.sh`. The master reaches the workers
over the private network with SSH and rsync, using a cluster key generated by Terraform; workers
accept SSH only from the master's security group.

Work split: phase 1, each worker builds shard `k` of 5 of the task list; phase 2, the master
merges the shards and builds the judge items; phase 3, each worker runs its judges
(w0: Qwen2.5-Coder-1.5B with context and point-wise conditions, w1: Qwen2.5-Coder-3B,
w2: Qwen3-1.7B with thinking and context, w3: Qwen3-4B, w4: Llama-3.2-3B and Gemma-3-4B);
phase 4, the master collects the verdicts and produces `results/`, `paper/main.pdf` and
`slides/slides.pdf`.

## Run

```bash
DESTROY=1 bash infra/run_experiment.sh
```

The script checks that the AWS credentials belong to account `602170263568`, creates the operator
SSH key if missing, detects the operator's public IP, runs `terraform apply`, waits for the
bootstrap, starts the orchestrator in `tmux` on the master, waits for `EXPERIMENT DONE`,
downloads `rjb-results.tgz` to `experiment-results/` and, with `DESTROY=1`, runs
`terraform destroy`. Progress:

```bash
ssh ubuntu@$(terraform -chdir=infra/terraform output -raw master_public_ip) tail -f orchestrate.log
```

Settings live in `infra/terraform/terraform.tfvars`. EC2 instances and the NAT gateway are billed
per hour. The cluster SSH key is passed through user data and stored in the Terraform state, so
the state file must stay private (it is excluded from Git).
